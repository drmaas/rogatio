## What is Rogatio?

Rogatio is a local-first tool for creating, reviewing, and running browser request and
response rules. It replaces a handful of ad-hoc Requestly workflows with one
version-controlled `.rogatio.json` file, a CLI, and a Chrome extension. The repository
file is canonical — moving changes between it and the browser requires an explicit import
or export.

![Rogatio routes browser requests through rules defined in a single .rogatio.json file](/rogatio/hero.svg)

## Why teams choose Rogatio

<CardGrid>
  <Card title="One source of truth" icon="document">
    A single version-controlled `.rogatio.json` describes every group and rule, so changes
    are reviewable, diffable, and revertible like any other code.
  </Card>
  <Card title="Runs in the browser" icon="rocket">
    Redirect, query, header, and mock rules execute entirely in Chrome — no proxy, no
    server, no round trips to a third party.
  </Card>
  <Card title="Local runtime, on demand" icon="puzzle">
    Response- and request-body rules use a device-local runtime that activates only when you
    explicitly start and connect it.
  </Card>
  <Card title="Safe by default" icon="shield">
    No accounts, hosted runtime, cloud sync, telemetry, or retained traffic history. Your
    traffic stays on your machine.
  </Card>
  <Card title="Test before you save" icon="approve-check">
    Dry-run any rule against a bounded batch of URLs offline to preview redirects and
    rewritten queries before committing.
  </Card>
  <Card title="Auditable & diffable" icon="git-branch">
    Because rules live in your repo, every change ships through the same pull request and
    review flow as the rest of your code.
  </Card>
</CardGrid>

## See it in action

```sh
# Install the CLI (requires Node 24+)
npm install -g @drmaas/rogatio

# Open the visual editor and edit .rogatio.json
rogatio edit

# Validate the project file
rogatio verify

# Start the local runtime for body-rewriting rules
rogatio runtime
```
